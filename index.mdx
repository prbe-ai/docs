Probe Research records the work, not just the numbers. A training run and its loss curve, yes — but also the eval sweep, the dataset pass, the literature review, the design decision someone made on a Tuesday, and the coding-agent session where all of it actually happened. It keeps them in one place, links them together, and makes them searchable by meaning.

## Three ways in, one backend

Probe has three write surfaces. They are not alternatives to each other — most teams use all three, because they cover different moments.

<CardGroup cols={3}>
  <Card title="Python SDK" icon="code" href="/sdk/quickstart">
    **From inside running code.** Metrics and spans as a training or eval script executes. The replacement for a `wandb.init()` call.
  </Card>

  <Card title="CLI" icon="terminal" href="/cli/overview">
    **From a shell.** Register projects and runs, attach files, write notes, import history, read anything back.
  </Card>

  <Card title="Agent plugin" icon="robot" href="/agents/overview">
    **From a coding agent.** Skills that teach Claude Code or Codex the workflow, plus a read-only MCP server so the agent can query lab history.
  </Card>
</CardGroup>

Everything lands in the same place: the [dashboard](/dashboard/overview) at [research.prbe.ai](https://research.prbe.ai), where the work is browsable, chartable, and searchable.

## What Probe holds

<AccordionGroup>
  <Accordion title="Structured experiment data" icon="chart-line">
    Projects, experiments, runs and run groups; metric series with arbitrary coordinate axes; spans and trajectories; immutable experiment versions; lineage edges between runs, artifacts and papers.

    See [projects and experiments](/tracking/projects) and [metrics](/tracking/metrics).
  </Accordion>

  <Accordion title="Files and code" icon="folder">
    Artifacts anchored to a run, experiment, project, workspace or the team's Shared folder — content-addressed, deduplicated by SHA-256, versioned. Plus non-disruptive code and environment snapshots that can be restored later.

    See [artifacts](/tracking/artifacts) and [snapshots](/tracking/snapshots).
  </Accordion>

  <Accordion title="Prose that survives the session" icon="pen">
    Three kinds, deliberately separate: a short `description` for identity, a teammate-facing Markdown **Overview**, and agent-facing **notes** with titled sub-notes and merge-on-push editing. Plus a shared **team note** injected into every agent session.

    See [notes](/tracking/notes).
  </Accordion>

  <Accordion title="Coding-agent sessions" icon="message">
    With capture on, your Claude Code and Codex sessions stream into the team knowledgebase: prompts, replies and the shell commands you ran. They become searchable evidence for why something was done.

    See [session capture](/agents/capture).
  </Accordion>

  <Accordion title="Literature and team rules" icon="book">
    Papers recorded against a research project — what each says, the repo read alongside it, and where the two disagree. And workflow memory: the conventions somebody declared out loud, returned to an agent when they apply.

    See [papers](/tracking/papers) and [team rules](/tracking/rules).
  </Accordion>
</AccordionGroup>

## Search that reads the whole record

One index covers all of it. An exact channel matches identifiers, names and paths; a semantic channel matches meaning. Both answer the same query, sectioned by source, with per-result provenance.

That is what makes the rest worth doing: a run you recorded in March is findable in September by describing it, and so is the session where you decided to run it.
