There is one guided path and several manual ones. Start with the guided path unless you have a reason not to.

## The guided path

```bash
npx probe-research install
```

The npm package is a thin launcher: it resolves and runs the real CLI, so you do not need Python tooling set up first. It signs you in, installs the plugins for the coding agents you pick, and offers to import work you already have.

`npx probe-research` with no verb opens the [wizard's main menu](/wizard/overview) instead — the right entry point when you are managing an install rather than creating one.

## CLI and SDK only

If you are instrumenting a training script and no coding agent is involved:

<CodeGroup>
```bash pip
pip install probe-research
```

```bash uv
uv tool install probe-research
```

```bash in a project
uv add probe-research
```
</CodeGroup>

One package ships both surfaces:

- `import probe` — the [Python SDK](/sdk/quickstart)
- `probe` — the [command-line tool](/cli/overview)

They are the same implementation with different ergonomics, so they have capability parity.

Then sign in:

```bash
probe login
```

## Agent plugins, by hand

The wizard runs exactly these commands. Running them yourself is supported — `probe wizard --action manual` prints the current set, generated from the same constants, so it cannot drift from what the wizard does.

<Tabs>
  <Tab title="Claude Code">
    ```bash
    claude plugin marketplace add prbe-ai/research-os-agent
    claude plugin install probe-research@research-os-agent       # tracking + MCP
    claude plugin install probe-research-tap@research-os-agent   # session capture
    ```

    Then finish setup from inside Claude Code with the Probe setup command, or from a terminal:

    ```bash
    npx probe-research install --agent claude
    ```
  </Tab>

  <Tab title="Codex">
    ```bash
    codex plugin marketplace add prbe-ai/research-os-agent
    codex plugin add probe-research@research-os-agent
    codex plugin add probe-research-tap@research-os-agent
    npx probe-research install --agent codex
    ```

    The third step authorizes this Codex device — Codex needs its own capture credential, separate from Claude Code's.
  </Tab>

  <Tab title="pi">
    ```bash
    npx probe-research install --agent pi
    ```

    <Warning>
    On pi, check the result rather than assuming it. A settings file that carries the package without its extensions loads the skills and the MCP manifest but never spawns the capture daemon — tracking reads as on while nothing is captured. `probe doctor` names that state.
    </Warning>
  </Tab>
</Tabs>

The two plugins are separate on purpose, because they are separate consent decisions: **tracking** adds skills and read-only search, **tap** streams your sessions to the team knowledgebase.

## MCP server

The read-only MCP server ships inside the tracking plugin, so a plugin install needs no extra step. To wire it into another MCP client:

```bash
probe-research-mcp            # stdio server
```

The hosted HTTP endpoint is `https://mcp.research.prbe.ai/mcp`. Credentials:

```bash
probe mcp status              # where the credential resolves from, and whether it works
probe mcp headers             # Authorization header as JSON
probe mcp env                 # the export line, for clients that only read the environment
```

The server prefers `PROBE_MCP_TOKEN`, a separately minted read-only token. It falls back to `PROBE_TOKEN` for local development and exposes no mutation tools either way.

## Keeping it current

Auto-update is on by default and runs in the background at session start. To check on it:

```bash
probe doctor                  # prints the LAST UPDATE ATTEMPT, not just the current version
```

That last line matters: a detached auto-updater that has been failing silently is otherwise invisible. To update now:

```bash
npx probe-research            # → Update to the latest version
```

The wizard's **On this device** block also carries a Versions section: what you have installed, what is published, and whether you are current.

To turn auto-update off, use the wizard's [Settings](/wizard/settings) screen, or:

```bash
probe wizard --no-auto-update --yes
```

<Note>
The CLI and the plugins version independently and a machine is routinely current on one and months behind on another. `probe doctor` grades all four components — CLI, SDK, plugin, tap — separately.
</Note>

## Removing it

```bash
npx probe-research            # → Uninstall Probe
```

That stops capture and imports, clears local import history, removes the plugins, and signs this device out — the tokens saved here are revoked. **Nothing already sent to your team's knowledgebase is touched.**

To sign out without uninstalling, choose **Sign out** instead; the plugins stay installed.

<Warning>
Credentials in your shell outrank the config file. If `PROBE_TOKEN`, `PROBE_MCP_TOKEN`, `PROBE_INGEST_TOKEN` or `PROBE_SERVICE_TOKEN` is exported in your environment, signing out clears the file but the CLI still authenticates. The wizard says so when it sees one — it cannot unset a variable in your parent shell.
</Warning>
